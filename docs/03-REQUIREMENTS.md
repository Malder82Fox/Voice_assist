# 03. Требования (предварительный baseline)

**Статус: PROPOSED.** Ни одна строка не означает, что функция уже реализована. Перед стартом разработки надо согласовать состав MVP, целевые ОС, аппаратные характеристики и критерии производительности.

Приоритет: **P0** — необходимо для базового MVP; **P1** — следующая итерация; **P2** — перспективная возможность.

## Функциональные требования

| ID | Приоритет | Требование | Проверка |
|---|---|---|---|
| FR-01 | P0 | Текстовый ввод и вывод без микрофона/сети | CLI тест без токенов |
| FR-02 | P0 | Разделить command parsing, routing, skills и представление | Тест без STT/TTS |
| FR-03 | P0 | Команды «помощь», «время», «дата», «состояние» | Автотесты |
| FR-04 | P0 | Неизвестная/непонятная команда даёт безопасный ответ | Нет side effects |
| FR-05 | P0 | Подключение навыка по явному интерфейсу; отключение навыка | Contract test |
| FR-06 | P0 | Отсутствующий секрет/сервис не ломает локальный режим | Fault injection |
| FR-07 | P1 | Speech-to-text с заменяемыми online/offline адаптерами | STT интеграционный тест |
| FR-08 | P1 | Text-to-speech с выбором доступного голоса и отказоустойчивостью | Без \`voices[n]\` |
| FR-09 | P1 | Push-to-talk / wake-word с конфигурируемым переключателем | Нет ложного «прослушивания» |

| FR-12 | P1 | Разрешения per skill/action, подтверждение внешних изменений | Negative security tests |
| FR-13 | P1 | Язык ru-RU в начале; расширяемая локализация | Языковые тесты |
| FR-14 | P1 | Администрируемые конфигурация и журналы без секретов | Логи и config tests |
| FR-15 | P2 | Диалоговое уточнение запроса, контекст сессии | Тест на неоднозначность |

## Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-01 | Privacy by default: не хранить аудиозаписи без разрешения, не отправлять их в сеть скрытно |
| NFR-02 | Offline-first для локального ядра; внешние API — явно опциональные |
| NFR-03 | Поддерживаемая версия Python/зависимостей, фиксируемая при старте, воспроизводимая сборка |
| NFR-04 | Совместимость с выбранной целевой ОС; первоначально рассмотреть Windows, Linux — как отдельный вопрос |
| NFR-05 | Unit/contract/integration tests, линтер, типизация и CI |
| NFR-06 | Структурированные сообщения об ошибках, диагностические коды, логирование без PII/секретов |
| NFR-07 | Таймауты, backoff, circuit breaker для внешних систем; команды не должны бесконечно зависать |
| NFR-08 | Отказ в доступе по умолчанию, минимальные права, проверка разрешений в конечной системе |
| NFR-09 | При недоступных/устаревших промышленных данных — статус «неизвестно/устарело», а не догадка |
| NFR-10 | Возможность остановить запись микрофона, полностью удалить локальную историю сессии |

## Измеряемые показатели (OPEN, не утверждены)

- Успешность распознавания русских команд: измерять на согласованном наборе фраз, в тишине и производственном шуме.
- Латентность голосового ответа: раздельно STT, NLU, API, TTS; пороги зафиксировать **после** выбора оборудования.
- Ложные срабатывания wake-word и доля ошибочных действий: определить приемлемые пороги.
- Доступность и деградация при отключении сети.
- Доля ответов CanLine OS с подтверждённым источником, временем данных и успешной авторизацией.

## Definition of Done будущего MVP

Документированный запуск на чистой машине; отсутствие обязательных внешних секретов в локальном режиме; тесты и CI зелёные; команда отказа обрабатывается понятно; нет обхода разрешений; есть инструкция для диагностики; инсталляция не требует старого \`env/\`.
