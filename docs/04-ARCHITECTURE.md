# 04. Целевая архитектура (PROPOSED)

Не начинать с выбора LLM. Сначала определить границы безопасности и типы команд.

## Обработка запроса

\`\`\`text
[Microphone] --> [Audio capture] --> [STT adapter] ----+
                                                        |
[Text UI / CLI] ---------------------------------------+--> [Normalizer]
                                                             |
                                                        [Intent resolver]
                                                             |
                                                    [Policy / Permissions]
                                                             |
                                                       [Skill Router]
                                                  /           |          \
                                           [Local]       [Personal]    [CanLine API]
                                           skills        connectors     (read-only)
                                                  \           |          /
                                                     [Result + metadata]
                                                             |
                                                    [Response formatter]
                                                       /           \
                                               [Text UI]       [TTS adapter]
\`\`\`

Технический модуль не должен одновременно принимать аудио, анализировать текст, отправлять сообщения и управлять компьютером.

## Подсистемы

1. **Transport / UI:** CLI, push-to-talk, tray, будущий web/mobile клиент.
2. **STT adapter:** интерфейс speech-to-text, локальная или внешняя реализация; флаги приватности.
3. **Intent resolver:** детерминированные команды первыми; NLU/LLM — опциональная подсказка, выход в структурированную схему.
4. **Authorization / Policy engine:** явное разрешение навыка, контекст пользователя, подтверждения и ограничения.
5. **Skill registry:** ID, версия, описание capability, входная схема, требуемые permissions, поддерживаемые языки.
6. **Connectors:** сторонние календарь/погода/сообщения, внутренний CanLine OS API; изоляция ошибок.
7. **Result formatter + TTS:** озвучивание только проверенных данных, ясное сообщение о неопределённости.
8. **Observability:** события по жизненному циклу команды; метрики без сырого аудио.

## Контракт навыка (концептуально)

**CommandRequest:** request_id, timestamp, locale, user_context (проверенный identity), source, intent, validated_parameters, confirmation_state.

**SkillDeclaration:** id, version, supported_intents, required_scopes, side_effect_level (read / write / critical), timeout_policy.

**CommandResult:** status (success / denied / clarification / error), human_text, structured_data, source_system, source_timestamp, audit_reference.

Контракты **не являются API, уже существующим в коде**. При разработке определить схемы и версионирование; не вставлять токены или персональные атрибуты в журнал событий.

## Режимы работы

- **Local-first:** системные команды, справка, время/дата и локальный TTS/STT без сети.
- **Connected:** явно разрешённые сервисы, отдельная индикация сетевого режима.
- **Enterprise/Plant:** интеграции через gateway/API CanLine OS, серверная авторизация и централизованный аудит.
- **Degraded:** недоступный внешний провайдер не блокирует локальные команды.

## Кандидаты технологий, НЕ утверждённый стек

- Python как язык прототипа/первой реализации, версия выбирается позже.
- Vosk, Whisper/faster-whisper для локального STT — сравнить качество русского, шум, требования к CPU/GPU, лицензии.
- Piper или системный TTS — сравнить естественность русского и доступность голосов.
- Опциональные wake-word движки — учитывать приватность, лицензии, false positive.
- HTTP API и/или событийная интеграция для навыков; API предпочтительнее прямого доступа к БД.
- LLM — только как слой интерпретации, без прямого произвольного исполнения инструментов.

Перед фиксацией в ADR провести proof-of-concept на целевом железе. **Не скачивать модель или подключать сервисы в рамках текущего документационного этапа.**

## Почему ассистент — отдельный репозиторий

Можно выпускать свой продукт и обновлять модели голоса независимо от CanLine OS. Промышленное приложение предоставляет строго определённые read API; ассистент остаётся сменяемым клиентом. Нельзя смешивать командный обработчик с PLC-протоколами.
