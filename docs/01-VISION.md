# 01. Product vision

## Одно предложение

**Voice Assist — модульный, ориентированный на приватность голосовой интерфейс, который может безопасно работать с личными и промышленными информационными системами, не подменяя их бизнес-логику.**

## Зачем

Обычные графические интерфейсы требуют открыть программу, найти нужный экран и вручную фильтровать данные. Голос удобен, когда заняты руки, пользователь находится у производственной линии или хочет быстро получить ответ о состоянии объекта. Для сложных операций он должен служить дополнительным каналом, а не единственным интерфейсом.

## Целевые пользователи (предварительно)

- Пользователь Windows: персональный помощник для справок, напоминаний и ограниченного набора действий.
- Инженер/начальник смены/менеджер предприятия: ответы по состоянию оборудования, событиям, OEE, заданиям и качеству.
- Администратор системы: управляет разрешениями, источниками и историями действий.

## Продуктовые направления

**A. Личный ассистент.** Голос/текст, базовые локальные команды, календарь и задачи по авторизованным интеграциям, помощь в поиске информации. Сложные действия только с подтверждением.

**B. Ассистент CanLine OS.** Запрашивает разрешённые данные через API платформы: «что происходит», «почему остановилось», «какие открыты задания». Первичная версия — исключительно read-only.

**C. Движок навыков.** Не специальный проект только для баночной линии: общий API адаптеров позволит применять ту же подсистему в другой среде.

## Что отличает удачный результат

1. Пользователь получает корректный и проверяемый ответ с указанием **системы-источника** и актуальности данных.
2. Можно заменить движок распознавания речи, TTS или NLP без переписывания навыков.
3. При потере сети локальные команды остаются доступны, сетевые явно сообщают о недоступности.
4. При неоднозначности («останови», «отправь», «удали») система не додумывает разрешение.
5. Для промышленных запросов учитываются tenant/site/asset, роль человека и аудит.

## Не цели первой реализации

- Не универсальный AGI-агент с доступом ко всему компьютеру.
- Не SCADA, не MES и не отдельная ERP.
- Не голосовой пульт управления оборудованием, ПЛК, safety interlocks или E-stop.
- Не обязательная постоянная отправка звука в облако.
- Не обязательная запись всех разговоров.

## Продуктовые принципы

- Голос — необязательный интерфейс; каждый значимый сценарий имеет текстовый fallback.
- Предсказуемые команды перед генеративным AI; LLM при необходимости выбирает **предложение**, а не бесконтрольное действие.
- Доступ к данным определяется серверными ролями и разрешениями, не распознаванием голоса.
- Ясные ограничения: выводить «данные отсутствуют» вместо выдуманного значения.
- Расширение через плагины с явно объявленными capabilities.
