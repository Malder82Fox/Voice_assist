## Проблемы поддержки

- Всё в одном \`main.py\` (~6 КБ), инициализация TTS/микрофона при импорте, бесконечный цикл.
- \`except: pass\` скрывает сбои и не различает «не услышал» и «сломался сервис».
- Фиксированный индекс голоса; крайне малое время первичного прослушивания; повторное прослушивание не отделено от обработки команд.
- Проверка времени будильника не организована независимым scheduler.
- Некоторые вызовы внешних сервисов без явных таймаутов и диагностических сообщений.
- Прямые вызовы OS и браузера; внешние команды не проходят авторизацию/подтверждение.
- Файлы \`test_*.py\` в основном ручные эксперименты, не автоматические регрессионные тесты.
- Отсутствует \`pyproject.toml\`/CI/ясная инструкция воспроизводимого запуска.
- В Git присутствуют Windows \`env/\` с зависимостями и \`.idea/\`, общее дерево \`master\` ~4 288 записей.

## ВАЖНО: секреты

В историческом \`test_pyowm.py\` обнаружен встроенный API-ключ. Не копировать его в новую документацию или код. Считать потенциально раскрытым, отозвать/заменить у поставщика API, проверить другие файлы и историю. Удаление файла в новом коммите **не удаляет секрет из Git history**. Вопрос изменения истории решать отдельно и осторожно.

## Стратегия наследования

Использовать старую ветку как **референс поведения**, а не как основу для немедленного слияния или побайтовой миграции: 
1. Составить матрицу полезных функций.
2. Выбрать современную архитектуру, версии Python и лицензии после возобновления.
3. Реализовать минимальные навыки заново с тестами.
4. Переносить внешние интеграции по одной, при наличии реальной потребности.

Сохранить ветку \`master\` до отдельного решения. Не запускать незнакомый код без осмотра токенов, зависимостей и сетевых действий.
