# 08. Roadmap — этапы на будущее

**Не согласованный календарный график.** Нет дедлайнов, оценок бюджета или назначенных исполнителей. Этапы выполняются только после отдельного решения возобновить проект.

| Фаза | Цель | Критерий выхода |
|---|---|---|
| 0. Discovery | Проверить целевые кейсы и актуальность старых зависимостей | Владелец утвердил MVP, платформы, угрозы и приоритеты |
| 1. Clean Core MVP | Пакет, текстовый CLI, command router, базовые локальные skills, тесты | Повторяемый запуск без сети и микрофона |
| 2. Voice Desktop | STT, TTS, push-to-talk, доступность, русский язык | Измеренный baseline качества на целевом железе |
| 3. Personal Skills | Напоминания, календарь, media, разрешённые desktop-действия | Разрешения + подтверждения + failure tests |
| 4. AI/NLU (опция) | Контекстный диалог, сложные формулировки | Валидируемая схема intents, запрет side effects без policy |
| 5. CanLine API Pilot | Один read-only объект/показатель, роли, on-prem | API контракт, RBAC, accuracy/staleness и audit tests |
| 6. Productization | Установка, обновления, документация, UI, релизы | Поддерживаемый lifecycle и privacy/security review |

## Правило очередности

**Не начинать с фазы 4 или 5**, пока не сделаны чистые интерфейсы навыков, базовая диагностика и модель разрешений. AI — не универсальный обход разрабатываемой архитектуры.

## Что вынести в первый спринт, когда вернёмся

- Решить, что первую версию действительно стоит делать: desktop для одного человека или CanLine demo. 
- Выбрать Python version/target OS, packaging, coding standards, dependency support policy.
- Утвердить один командный контракт, 3–5 тестовых команд и безопасный отказ.
- Отдельно проанализировать историю \`master\` и закрыть риск API-ключей.
- Описать acceptance tests и автоматическую проверку pull requests.

## Эволюция возможностей

В будущем можно добавить мультиязычность, альтернативные STT/TTS/LLM, короткую память диалога, UI-клиенты, локальный Home Assistant интегратор, корпоративные task workflow интеграции. Решать по реальным сценариям, а не включать сразу всё.

**Stop/go gate:** перед каждой фазой проверить полезность, privacy и безопасность; при отрицательном результате допускается остаться с текущим read-only/text вариантом.
