# 07. Security & privacy baseline

**Статус: обязательные ограничения на будущее; не означает, что проведён security audit работающего продукта.**

## Текущая опасность исторического кода

Исторический \`master\` содержит закоммиченное окружение \`env/\` и по крайней мере один встроенный внешний API-ключ в тестовом файле. Требуется **отозвать/сменить ключ**; проверить все учетные данные и историю. Не сохранять секреты в docs/Issue/PR. Удаление файла не удаляет его из предыдущих коммитов. При необходимости очищать историю — отдельная задача с оценкой влияния на клоны и форки.

## Модель угроз (набросок)

- Ложноположительное распознавание речи и команды со стороны постороннего человека/фонового звука.
- Prompt injection или инструкции из внешнего сообщения, веб-страницы, производственного alarm text.
- Случайная утечка аудио, стенограмм, адресатов, коммерческих и производственных данных.
- Excessive permissions: авторизация только по голосу или доверие клиентскому tenant_id.
- Небезопасные интеграции: shell execution, произвольные URLs, токены в коде/логах, SSRF.
- Некорректное управление критичной техникой при неверно распознанной команде.
- Устаревшие данные и hallucinations, особенно в промышленном сценарии.

## Обязательные контрмеры

1. **Default deny.** Каждый skill объявляет scopes и side-effect level. Неподдержанная команда ничего не выполняет.
2. **Authenticated identity.** Голос не равен личности; нельзя выдавать доступ только из-за wake-word или голоса.
3. **Server-side authorization.** Проверять user, tenant, plant, asset и action в целевой системе.
4. **Separation of duties.** CanLine MVP — read-only; не выдавать ассистенту credentials с управлением установками.
5. **Human confirmation.** Для отправки сообщений/создания задач требуется подтверждение конкретного действия; для опасного промышленного управления подтверждение само по себе не делает его допустимым.
6. **No arbitrary execution.** Запрет \`eval\`, свободных shell команд, незарегистрированных программ/URL, инструментов без allowlist.
7. **Structured commands.** Результат NLU/LLM — предложенные структурированные данные, которые валидируются схемой и policy; внешние тексты не могут расширить права.
8. **Secrets management.** Environment/локальное хранилище учётных данных/secret manager; никогда не включать ключи в sample, traces или тестовые фикстуры.
9. **Network security.** TLS для удалённых сервисов; timeouts; ограничение endpoints, rate limits; для on-prem оценить mTLS и сегментацию сети.
10. **Privacy.** Микрофон запускается явно; индикация записи; raw audio по умолчанию не сохранять; сроки хранения журналов задать политикой.
11. **Data provenance.** В ответе отражать источник и актуальность. Отказывать в уверенном ответе без достоверных данных.
12. **Dependency hygiene.** Проверка лицензий, security scan, воспроизводимые сборки, подписанные releases по потребности.

## Особый запрет для промышленного применения

Voice Assist не реализует E-stop, bypass safeguards, изменение setpoints, сброс interlocks, запуск/останов оборудования или PLC write. Любое рассмотрение control use cases требует самостоятельной risk assessment, функциональной безопасности, инженерного контроля и отдельного допуска — **не часть дорожной карты MVP**.

## Перед публикацией/пилотом

Проверить лицензирование STT/TTS-моделей и компонентов, трансграничную обработку аудио, регуляторные требования на площадке и корпоративную политику данных. Создать incident response checklist и revoke flow.
